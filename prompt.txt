WHAT THIS IS
------------
A multi-tenant Restaurant Operating Management System (ROMS) built from PLAN.md
as a Bun workspace monorepo:
  apps/admin   → SvelteKit admin + POS (Svelte 5, Tailwind v4, shadcn-svelte,
                 TanStack Query, Eden Treaty client)
  apis/admin   → separate ElysiaJS API (Zod/Standard Schema, Drizzle, PostgreSQL)
  packages/    → contracts (Zod schemas/DTOs), config (typed env), database
                 (Drizzle schema/client/migrations/seed), utils (money/result/…)
Config files: AGENTS.md and .mcp.json now live at the REPO ROOT (moved out of apps/admin).

Phase 1 — Foundation
- Bun workspace monorepo at E:\workspace\ps with root package.json, tsconfig.base,
  docker-compose (Postgres 17 + Redis 7), .env.example, prettier config/ignore,

  test, no Docker) and postgres.js (production). createTestDatabase() for tests.

Phase 2 — Auth & tenancy
- Auth: HS256 JWT access tokens + rotating hashed refresh tokens (Argon2id via
  Bun.password), sessions, OTP, password reset, /auth/me.
- Tenants, branches, users, roles, granular permissions, audit logs.
- Tenant/branch context resolved server-side from token + x-branch-id header.

Phase 3/4 — Catalog, orders, payments, inventory, purchasing, recipes
- Categories, products, variants, modifier groups, POS search.
- Orders: single server-authoritative pricing engine (bigint money, no floats),
  explicit order state machine, transactional stock deduction/reversal.
- Payments: cash/card/bank/JazzCash/Easypaisa, idempotent capture, refunds, cash
  movements. Inventory: stock levels + append-only movements + transfers.
- Purchasing: suppliers, purchase orders, goods receiving → stock + supplier
  ledger (transactional), supplier payments, purchase returns.
- Recipes: versioned recipes, ingredient costing, production runs that consume
  ingredients and produce output stock.

CURRENT STATE / KNOWN ISSUES (open items for next session)
1. The composed API type hit TypeScript's depth limit (TS2589) once the last four
   modules (promotions, storage, table-ops, reports-extra) were wired in. To keep
   a clean typecheck they are currently NOT composed in apis/admin/src/app/index.ts
   (their source files exist and typecheck on their own). Re-wiring likely needs
   reducing Elysia plugin depth (e.g. share one guard plugin instance / split into
   grouped sub-apps / annotate plugin types).
2. Web dev server returns HTTP 500 on http://localhost:5173/ (an SSR error page;
   the login → dashboard flow was previously verified in a browser). Needs a look
   at the SvelteKit dev output when the app is run interactively.
3. /api/openapi serves the Scalar HTML page, but the Scalar UI loads its JS bundle
   from https://cdn.jsdelivr.net/npm/@scalar/api-reference@latest . If that CDN is
   blocked on the new machine the docs page appears blank. Fix: self-host the
   Scalar bundle and set `scalar: { cdn: '/scalar/scalar-standalone.min.js' }`
   (serve via @elysia/static), or switch provider.
4. Redis/OTel/PWA-offline/i18n are intentionally not implemented (memory cache is
   used; structured Pino logging is OTel-ready).
5. Playwright E2E is configured (apps/admin/playwright.config.ts, e2e/pos.spec.ts)
   but browsers were not installed, so E2E has not been executed.

HOW TO RUN ON THE NEW MACHINE
   bun install
   cp .env.example .env          # defaults to PGlite (no Docker needed)
   bun run db:migrate
   bun run db:seed               # demo tenant; login owner@demo.test / Password123
   bun run dev:api               # http://localhost:3000  (docs at /api/openapi)
   bun run dev:admin             # http://localhost:5173
Optional real Postgres: docker compose up -d; set DATABASE_DRIVER=postgres + DATABASE_URL.
